# 기능 요구사항

상태: 확정(MVP 범위)  
원본: `docs/input/Requirements.md`

각 기능은 사용자 동작, 입력, 검증, 상태, 오류, 데이터 처리와 완료조건을 기준으로 구현한다.

## 공통 규칙

- Room 데이터가 화면의 Source of Truth다.
- 로컬 작업에서 불필요한 전체 화면 로딩을 표시하지 않는다.
- 저장·수정·삭제 중에는 동일 요청의 중복 실행을 막는다.
- 실패 시 입력이나 기존 데이터를 임의로 버리지 않는다.
- 내부 예외, 스택 트레이스와 DB 오류 코드를 사용자에게 노출하지 않는다.
- 삭제는 명시적인 사용자 확인 후 실행한다.

## FR-01 TODO 등록

- 흐름: 목록의 추가 → 입력 → 저장 → 선택 날짜 목록 복귀
- 입력: 제목, 날짜, 선택 시간, Category, 선택 알림
- 검증: 제목과 날짜 필수, 공백 제목 불가, 시간 없이는 알림 불가
- 알림: `1440분 전`과 `15분 전`을 동시에 선택할 수 있다.
- 초기 상태: 빈 입력을 표시하며 진입한 목록의 선택 날짜를 기본값으로 사용할 수 있다.
- Category: 미선택 시 시스템 기본 Category `일반`을 사용하며 Category 없는 Todo는 저장하지 않는다.
- 과거 날짜와 과거 시간의 TODO도 저장할 수 있다.
- 저장: Todo와 Reminder를 DB에 저장한 뒤 권한이 있고 미래 시각인 Reminder만 시스템 알람으로 등록한다.
- 실패: 입력을 유지한다. 알림 권한 또는 알람 예약 문제로 Todo와 Reminder 저장을 롤백하지 않는다.
- 완료: 목록 반영, 재실행 후 유지, 선택한 유효 알람 등록

## FR-02 TODO 수정

- ID로 기존 TODO와 Reminder를 조회해 입력값으로 표시한다.
- 등록과 같은 입력 검증을 적용하며 존재하지 않는 ID는 수정할 수 없다.
- 조회 중에는 필요한 로딩 상태를 표시한다.
- 저장 실패 시 편집값을 가능한 한 유지한다.
- 날짜, 시간 또는 Reminder 변경 시 기존 알람을 취소하고 재등록한다.
- 완료: 목록과 DB에 변경이 유지되고 시스템 알람도 변경값과 일치

## FR-03 TODO 삭제

- 삭제 확인 UI에서 사용자가 확정한 뒤 삭제한다.
- 존재하지 않는 ID 요청은 안전하게 처리한다.
- 실패 시 목록에서 먼저 제거하지 않고 실패를 안내한다.
- Todo, 연결 Reminder와 미래 시스템 알람을 모두 제거한다.
- 삭제 후 결과가 없으면 날짜 빈 상태를 표시한다.

## FR-04 완료 상태 변경

- TODO를 완료 또는 미완료로 전환하고 `isCompleted`를 저장한다.
- 화면에 즉시 반영하되 저장 실패 시 DB와 UI가 불일치하지 않도록 복구한다.
- 미완료 필터가 활성화되어 있으면 완료 항목을 결과에서 제외한다.
- 완료 시 아직 실행되지 않은 미래 알람을 모두 취소하되 Reminder는 유지한다.
- 미완료로 되돌리면 현재보다 미래인 Reminder만 다시 등록한다.

## FR-05 날짜별 조회

- 앱 최초 실행 시 오늘을 선택한다.
- 이전·다음 날짜 이동 시 선택 날짜의 TODO만 표시한다.
- 결과가 없으면 `등록된 TODO가 없습니다.`를 표시한다.
- 날짜 선택값의 앱 재실행 간 영속화는 MVP 필수가 아니다.
- 조회 실패 시 목록을 불러오지 못했음을 안내한다.
- 정렬은 시간이 있는 항목을 먼저 시간 오름차순으로 표시하고, 시간이 없는 항목을 뒤에 표시한다. 같은 시간은 생성순 오름차순이며 완료 여부는 정렬에 영향을 주지 않는다.

## FR-06 종류 생성

- 종류 관리 화면에서 이름을 입력하고 저장한다.
- 빈 문자열과 공백만 있는 이름은 허용하지 않는다.
- 기존 Category 이름 및 시스템 이름 `일반`과 중복된 이름은 허용하지 않는다.
- 사용자는 사전 정의 팔레트에서 표시 색상을 선택한다.
- 신규 사용자 Category의 `sortOrder`는 현재 사용자 Category 목록의 마지막 순서로 자동 지정하며 사용자가 번호를 입력하지 않는다.
- 저장 실패 시 입력값을 유지한다.
- 생성한 Category는 목록과 TODO 편집 화면에 표시되고 재실행 후 유지된다.
- 시스템 기본 Category `일반`은 최초 DB 생성 시 존재하며 사용자가 생성하는 Category가 아니다.

## FR-07 종류 수정

- ID로 존재하는 종류의 이름을 수정한다.
- 빈 문자열과 공백 이름은 허용하지 않는다.
- 기존 이름과 중복되는 이름은 허용하지 않는다.
- 시스템 기본 Category `일반`은 이름을 변경할 수 없다.
- 사용자는 사용자 Category의 색상을 사전 정의 팔레트에서 변경할 수 있다.
- `일반`의 색상은 변경할 수 없다.
- 실패 시 기존 값을 유지한다.
- 변경 이름은 해당 종류를 사용하는 TODO에도 표시되고 재실행 후 유지된다.

## FR-08 종류 삭제

- AlertDialog에서 사용자가 확인한 뒤 사용자 Category를 삭제한다.
- 시스템 기본 Category `일반`은 삭제할 수 없다.
- 사용 중인 Category도 삭제할 수 있으며, 연결된 모든 Todo의 `categoryId`를 `일반` ID로 변경한 뒤 Category를 삭제한다.
- Todo 재지정과 Category 삭제는 하나의 DB transaction으로 처리하며 연결 Todo는 삭제하지 않는다.
- 확인 문구에는 TODO가 삭제되지 않고 `일반`로 변경된다는 내용을 안내한다.

## FR-09 종류 필터

- 존재하는 Category 또는 `전체`를 선택한다.
- 선택 날짜 안에서 해당 종류의 TODO만 표시한다.
- `전체` 선택 시 종류 조건을 해제한다.
- 결과가 없으면 필터 결과 없음 상태를 표시한다.
- 필터 선택값의 재실행 간 영속화는 MVP 필수가 아니다.
- 필터의 Category 목록은 저장된 `sortOrder`를 사용하고 `일반`을 최상단에 표시한다.

## FR-10 미완료 필터

- 활성화하면 `isCompleted = false`인 항목만 표시하고 해제하면 전체를 표시한다.
- 날짜 및 종류 조건과 동시에 적용할 수 있다.
- 결과가 없으면 필터 결과 없음 상태를 표시한다.

## FR-11 복합 필터

- 날짜는 필수 조건이며 선택 종류와 미완료 여부를 AND로 적용한다.
- 활성화된 모든 조건을 만족하는 TODO만 표시한다.
- 일반적인 로컬 조회에는 전체 화면 로딩을 사용하지 않는다.

## FR-12 알림 설정

- 날짜와 시간이 있는 TODO에서만 알림을 선택한다.
- 알림 시각은 `TODO 예정일시 - 사전알림분`으로 계산한다.
- `15`, `1440`을 각각 또는 동시에 저장한다.
- Reminder 저장 후 시스템 Alarm을 등록하며 DB에서 재구성할 수 있어야 한다.
- 계산 시각이 이미 과거면 Reminder만 저장하고 시스템 Alarm은 등록하지 않는다.
- Reminder를 처음 활성화하려는 시점에 알림 표시 권한을 요청한다.
- 알림 권한이 없으면 Todo와 Reminder를 저장하고 Alarm은 등록하지 않으며 사용자에게 안내한다.
- Exact Alarm이 가능하면 사용하고, 권한이 없으면 허용된 Inexact Alarm으로 fallback한다.
- 예약 실패는 Todo와 Reminder를 롤백하거나 UI를 무한 로딩시키지 않고 별도 안내 상태를 제공한다.

## FR-13 데이터 영속화

- Todo, Category와 Reminder를 Room에 저장한다.
- 앱 종료와 프로세스 재시작 후 DB에서 복원한다.
- DB 접근 실패는 앱 종료 대신 오류 상태로 표시한다.
- 앱 제거 시에는 Android 앱 데이터 정책에 따라 삭제될 수 있다.

## FR-14 알람 갱신과 복구

- 날짜, 시간 또는 Reminder 수정 시 기존 알람을 취소하고 다시 등록한다.
- TODO 삭제 시 알람 취소와 Reminder 삭제를 보장한다.
- 기기 재부팅 후 DB의 미래 Reminder만 재등록하며 이미 지난 Reminder는 알림을 발생시키지 않는다.
- 알람은 Todo와 Reminder를 식별하는 안정적인 고유 ID를 사용한다.

## FR-15 Category 정렬과 색상

- Category 관리 화면에서 사용자 Category를 drag & drop으로 재정렬한다.
- `일반`은 `sortOrder = 0`으로 최상단에 고정하며 이동할 수 없다.
- 사용자 Category끼리만 이동할 수 있고 `sortOrder`는 `1`부터 일관된 연속 순서로 갱신한다.
- 변경 순서는 하나의 일관된 DB 작업으로 저장하고 앱 재실행 후 유지한다.
- 신규 사용자 Category는 현재 목록의 마지막에 추가한다.
- TODO 등록·수정 선택 목록과 TODO 목록 필터도 저장된 Category 순서를 사용한다.
- Category 생성·수정 화면에서 작은 원형 색상 버튼을 누르면 사전 정의 팔레트를 표시한다.
- 자유 RGB/HEX 입력은 제공하지 않으며 서로 다른 Category의 같은 색상 사용을 허용한다.
- `일반`은 `NEUTRAL`로 고정한다.
- Category를 표시할 때 색상과 이름을 함께 사용한다.

## 사용자 오류 메시지 기준

- `제목을 입력해주세요.`
- `날짜를 선택해주세요.`
- `시간을 설정해야 알림을 사용할 수 있습니다.`
- `TODO를 저장하지 못했습니다. 다시 시도해주세요.`
- `TODO를 삭제하지 못했습니다. 다시 시도해주세요.`
- `알림을 사용하려면 알림 권한이 필요합니다.`
- `일정은 저장되었지만 알림을 예약하지 못했습니다.`

문구는 문자열 리소스로 관리하며 실제 UI 맥락에 맞게 동등한 의미로 다듬을 수 있다.

## 기능 완료의 공통 조건

- 정상 흐름, 빈 상태, 검증 실패와 저장소 실패를 처리한다.
- UI 상태와 DB 상태가 일치한다.
- 프로세스 재실행 후 영속 데이터가 유지된다.
- 관련 Presenter, DAO 또는 UI 테스트가 통과한다.
