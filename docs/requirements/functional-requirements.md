# 기능 요구사항

상태: 확정(MVP 기능 범위)

## 확정된 기능

MVP 기능은 `product-requirements.md`와 승인된 `docs/design/` 문서에 확정되어 있다. 기존 TODO CRUD, Category CRUD·정렬·색상 및 알림 정책을 해당 문서에 따라 적용한다. 새 기능의 명세에는 아래 항목을 기록한다.

- 사용자 동작
- 입력값과 유효성 조건
- 정상 처리 결과
- 빈 상태와 로딩 상태
- 오류 조건과 사용자 안내
- 데이터 저장 및 삭제 정책

## 기능 명세 템플릿

새 기능은 다음 형식으로 이 문서 또는 별도 기능 문서에 기록한다.

```text
기능명:
목적:
사용자 흐름:
입력:
출력:
유효성 규칙:
빈 상태:
오류 처리:
완료 조건:
```

## TODO 목록 필터

- 조회 조건은 선택 날짜, 선택 Category, 미완료 여부의 AND다.
- 기본값은 오늘, Category 전체(`null`), 완료 여부 전체(`false`)다. 전체는 실제 Category가 아니다.
- 날짜 이동 시 Category·완료 여부 필터를 유지하며 앱 재실행 간 필터 상태는 저장하지 않는다.
- Category 선택지는 전체 다음에 DB의 저장 순서를 사용하고 이름·색상 변경을 반영한다.
- 선택된 Category가 삭제되면 전체로 초기화한다. 기존 TODO의 일반 재지정은 기존 삭제 transaction을 따른다.
- 미완료 조건에서 완료한 TODO는 Room 조회 결과 갱신으로 제외한다.
- 날짜에 TODO가 없으면 `등록된 TODO가 없습니다.`, 날짜의 TODO는 있으나 필터 결과만 없으면 `조건에 해당하는 TODO가 없습니다.`를 표시한다.
- 조회 실패는 오류 상태로 표시하며 빈 결과는 정상 상태다. 필터 조작은 저장 데이터를 변경하지 않는다.

## 사용자 지정 Reminder 시간 (Phase 16)

- 시간이 지정된 TODO에 대해 프리셋(`15분 전 (15)`, `1시간 전 (60)`, `1일 전 (1440)`) 및 `[+ 직접 설정]`을 통해 복수의 Reminder를 설정할 수 있다.
- 직접 설정은 일(`days`), 시간(`hours`), 분(`minutes`) 입력을 받아 `offsetMinutes = days * 1440 + hours * 60 + minutes`로 계산한다.
- 유효 조건은 `days >= 0`, `hours >= 0`, `minutes >= 0`이며 합산된 `offsetMinutes > 0`(산술 오버플로 방지 상한 이내)이어야 한다. `0분`(정각), 음수, 숫자가 아닌 입력은 허용하지 않는다.
- 동일한 TODO에 동일한 `offsetMinutes`는 중복 저장하지 않는다. 직접 설정으로 프리셋 값(`15`, `60`, `1440`)을 입력하면 해당 프리셋 선택으로 귀속되며 사용자 지정 목록에 중복 생성하지 않는다.
- 추가된 사용자 지정 알림은 편집 화면에서 개별 `[수정]` 및 `[삭제]`가 가능하다.
- 시간이 없는 TODO는 Reminder를 선택하거나 직접 설정할 수 없으며, 시간을 제거하면 선택된 프리셋과 사용자 지정 알림을 모두 해제한다.
- UI 및 상세 화면에서 여러 Reminder는 먼 시점부터 가까운 시점 순(`offsetMinutes` 내림차순)으로 일관되게 표시하며, `0`인 단위는 생략하여 표시한다(예: `15분 전`, `1시간 전`, `2시간 30분 전`, `1일 전`, `3일 4시간 전`).

## 구현 범위 제한

- 요구사항이 미정인 기능은 화면이나 데이터 계약을 임의로 확정하지 않는다.
- 삭제처럼 복구하기 어려운 동작에는 명시적인 요구사항이 필요하다.
